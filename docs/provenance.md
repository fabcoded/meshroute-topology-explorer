# Provenance

Origin of the code, its inputs and the numbers in the specification. All commits but one name their author in a
`Provenance:` trailer (`human` or `agent <tool>/<model>`); one early merge commit does not. Sign-off (DCO) is required
from the release commit 0.1.0 on (AGENTS.md).

## How the code was written

- Claude models (Opus 5.5, Sonnet 5.5) wrote the code in Claude Code from 2026-10-31, in work packages directed by
  Fabian Schwamborn through a coordinating session that wrote the briefs.
- Earlier unpublished experiments by the author were discarded with all their code on 2026-10-31; the repository
  starts from scratch.
- Clean room: implementers were fresh agents given the specification, the Home Assistant docs and anonymized captures
  only, with no contact with earlier code; no other project's code was read (AGENTS.md).
- Reviews: separate agents (Claude Opus 5.5, Claude Fable 5.1) reviewed the setup (legal, privacy), the
  specification, the Home Assistant API use against 2026.10.2, security, the clean room and the sample numbers, which
  they recomputed independently. Later packages were checked by tests, parity runs and the coordinating session;
  Codex (OpenAI) reviewed design and texts in two rounds.
- Model training was switched off for the author's Claude account before work began (2026-10-31).
- Design: texts, controls, line styles and the legend follow the owner's private design drafts "Meshroute Design v1"
  (2026-11-01); the resulting rules are in spec 8 and 9. The 18 device pictures are transcribed from round 6.2 of the symbol drafts (design
  input ChatGPT (OpenAI), via Fabian Schwamborn; completed by Claude) into `graph/symbols.js`. The brand icon is an
  agent's own drawing, generated by script.

## Inputs

- Fixtures: anonymized captures of the author's own ZHA and Matter networks (`tests/fixtures/zha-sample.json`,
  `tests/fixtures/matter-sample.json`), made with `tools/anonymize_capture.py`. The author's private notes on his
  network informed the specification.
- Home Assistant core 2026.10.1 and 2026.10.2 and the frontend, read for API contracts and conventions only:
  `websocket_api`, `helpers/storage`, ZHA's `websocket_api.py` (attribute read), `helpers.py` (`get_zha_gateway`),
  `const.py`, `websocket_api/const.py`; frontend `navigate.ts`, routes, theme and locale fields of `src/types.ts`, the
  `hass-more-info` event; home-assistant-js-websocket connection events, errors and `sendMessage` (fire-and-forget,
  used for the scan); websocket error codes (`not_supported`, `unknown_command`).
- zigpy 2.4.0 (`device.py` relays, `application.py` handle_relays and build_source_route_to, `appdb.py`,
  `topology.py`, `util.py` filter_relays) and zigpy-znp 1.1.1 (`ZDO.SrcRtgInd`), read in the installed packages for
  the data model. The zha library, bellows and zigpy-deconz were not available; other radio libraries are unverified.
- matter.js server: `packages/ws-client/src/models/model.ts` (NetworkTopologyConnection) and
  `docs/websocket-api-schema-changelog.md` (schema 13), handed to the agents as quotes.
- Zigbee specification r22 (CSA 05-3474-22, 2017-04-19, public PDF), sections 3.4.8.3.2, 3.6.3.1, 3.6.3.3,
  3.6.3.5.2 and Mgmt_Lqi_rsp. Zigbee profile, ZCL cluster and attribute identifiers were written from the agent's
  knowledge of the public specifications, not re-read; every identifier on the sample agrees with its model name
  (28 lights, 4 outlets, 7 buttons, 5 motion sensors).
- Thread reception model: OpenThread, matter.js and vendor documentation, sources S1–S15 in
  [thread-quality-model.md](thread-quality-model.md).
- Methods: Eades 1984; Fruchterman and Reingold 1991; Barnes and Hut 1986; Dijkstra 1959; the seeded generator
  mulberry32 (Tommy Ettinger, public domain).
- Platform: WCAG 2.2; WAI-ARIA Authoring Practices (tabs, listbox, menu button, switch, dialog, disclosure); MDN on
  Canvas 2D, Pointer Events, the dialog element, the colour input and CSS container queries; SVG 1.1 implementation
  notes F.6.5 (arc conversion); RFC 6455; Python documentation.
- Palettes: Okabe and Ito 2008.

## Structure comparison before a release

- The owner's main session runs it, agents never read the comparison sources: in a fresh temp dir outside the repo,
  `npm pack <pkg>@<exact version>` for each comparison package and unpack; run `python3 tools/structure_compare.py
  --theirs <dir>` (usage in the tool's docstring); look only at our line ranges at or above the threshold; delete the
  temp dir.
- Record one line per run here: date, tool revision, package versions, maximum pair share and longest run. Results
  are not part of this procedure.
